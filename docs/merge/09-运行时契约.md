`siliconflow_draw, tavily, xai_draw, zhipu_draw, zhipu_search`

## 类2 — METADATA 与 exports 不一致

| 包 | METADATA 声明 | 运行时 exports |
|---|---|---|
| `automatic_ui_base` | 含 `usage_advice` | **无** `usage_advice`，多出 `main` |
| `automatic_ui_subagent` | 顶层 `tools: []` | 有 `usage_advice` 等 5 个 |

真机：`automatic_ui_base:usage_advice` → `tool not found`
→ schema（`listTools`）把一个**不存在的工具名**交给了模型。

## 类3 — state-gated 契约（states + condition + inheritTools）

`automatic_ui_subagent.js:20` 顶层 `tools: []`；`:22` 起：

```js
states: [{ id: "virtual_display", condition: "ui.virtual_display",
           inheritTools: true, tools: [{ name: "usage_advice" }] }]
```

`listTools` 只读顶层 `tools`，所以设备 dump 里该包 **0 工具**；而 exports 实有 5 个，
真机 `automatic_ui_subagent:usage_advice` 返回 `success:true` + 正文。
→ **第三类工具声明机制**，schema 生成需要感知 `states`。

## 类4 — 诊断盲区：加载失败是静默的

`executeTool`（`OperitJsRuntime.kt:236-243`）丢弃模块 eval 的返回值，`loaded.add(pkg)` 无条件：

```kotlin
rt.eval(buildString { /* module 包装 + 源码 */ }, "$pkg.js")   // 返回值被丢弃
rt.executePendingJobs()
loaded.add(pkg)
```

**压到下一层**（谁吞了异常）：不是 Kotlin。
`QuickJsNativeRuntime.eval`（`android/operit_quickjs/.../QuickJsNativeRuntime.kt:76`）只是
`QuickJsNativeBridge.nativeEvaluate(...)` → `parseEvalResult(...)`，**不抛**；
异常在 **native 层**被捕获并结构化返回（`EvalResult.success=false`）。

**待办（诊断增强，不单独开笔）**：在 `executeTool` 检查加载 eval 的 `success`，
失败时 `diag("load failed <pkg>: <error>")` 并返回明确的 load error，
而不是让后续查找退化成含糊的 `tool not found`。

# 许可证合规说明（合并前必读）

## 一、两个上游的许可证

| 项目 | 许可证 | 关键义务 |
|---|---|---|
| `AAswordman/Operit` | **LGPL-3.0-only** | 修改部分需开源；保留版权声明 |
| `Chevey339/kelivo` | **AGPL-3.0** | **网络提供服务时也必须提供完整源码**；衍生作品须同许可 |
| QuickJS（Operit 内嵌） | **MIT** | 保留版权与许可声明 |
| MNN | Apache-2.0 | 保留 NOTICE |
| llama.cpp | MIT | 保留声明 |

## 二、合并后的许可选择

**LGPL-3.0 的代码可以被并入 AGPL-3.0 作品**（LGPLv3 明确允许，且 GPLv3 §13 与 AGPLv3 互为兼容通道）。

→ **合并工程的最终许可证必须是 `AGPL-3.0`**（两者中更严格的一个）。

### 必须做的事

1. **保留两份原始 LICENSE 文件**，放在 `third_party/` 下：
   ```
   third_party/operit/LICENSE      (LGPL-3.0)
   third_party/kelivo/LICENSE      (AGPL-3.0)
   third_party/quickjs/LICENSE     (MIT)
   ```
2. **保留原作者版权声明**，在 `NOTICE` / `README` 中注明：
   ```
   本工程基于以下开源项目合并开发：
   - Operit AI (https://github.com/AAswordman/Operit), LGPL-3.0-only
   - Kelivo   (https://github.com/Chevey339/kelivo),  AGPL-3.0
   ```
3. **整个工程以 AGPL-3.0 发布**，并公开全部源码。
4. **若提供网络服务**（如 Operit 的 WebChat / HTTP API），依 AGPL §13 **必须向使用者提供源码**。
5. 移入的 JS 工具包（`assets/packages/*.js`）**保留文件头的 METADATA 与原作者信息**。

## 三、风险提示

| 风险 | 说明 |
|---|---|
| ⚠️ 商标 | Operit / Kelivo 的名称与 Logo 受商标/版权保护，**不要用同名发布**，建议改用自定名称 |
| ⚠️ AGPL 传染性 | 一旦并入 AGPL 代码，**整个 App 必须以 AGPL 开源**，不能闭源分发 |
| ⚠️ 应用商店 | 部分商店对 AGPL 应用有额外要求，上架前需确认 |
| ⚠️ Operit 子模块 | `OperitTerminalCore` 许可证为 "NOASSERTION"（未声明），**使用前需单独确认授权** |

## 四、建议做法

```
你的合并工程 (AGPL-3.0)
├── LICENSE                    ← AGPL-3.0 全文
├── NOTICE                     ← 上游版权声明汇总
└── third_party/
    ├── operit/LICENSE         ← LGPL-3.0 原文
    ├── kelivo/LICENSE         ← AGPL-3.0 原文
    └── quickjs/LICENSE        ← MIT 原文
```

**"仅复用代码逻辑"这个说法在法律上不成立**——代码就是代码，复制即受许可约束。
好在这两个许可证**都允许**你这么做，代价是**你也必须开源**。

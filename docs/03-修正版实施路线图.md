# 修正版实施路线图

> 原则：**先做能在本机验证的，再做必须换机器的。**
> 绝不在没有编译环境的情况下声称「已完成」。

## 阶段划分

### ✅ 阶段 0 — 源码盘点（已完成）

产出：
- `01-源码盘点与可行性评估.md`（实测数据 + 4 处方案修正）
- `02-Host-API映射表.md`（140 个接口的完整清单）
- 两份原始源码解包在 `ref/`

---

### 🔜 阶段 1 — 工程骨架 + QuickJS 引擎移植

**目标**：让 Kelivo 能执行一段 JS。

| 步骤 | 操作 | 可行性 |
|---|---|---|
| 1.1 | 以 Kelivo 为 base 建合并工程 | ✅ 本机可做 |
| 1.2 | 把 Operit `quickjs/` 模块拷进 `android/`，并在 `settings.gradle` 注册 | ✅ 本机可做 |
| 1.3 | 移植 `QuickJsNativeRuntime.kt` / `QuickJsNativeHostDispatcher.kt` / `QuickJsNativeCompatScriptBuilder.kt` | ✅ 本机可做 |
| 1.4 | 跑通最小用例：`1+1=2` 与 `console.log` | ❌ **需 Flutter+Android SDK，本机不可行** |

> 关键：1.2/1.3 是**纯文件搬运 + 包名改写**，本机可完成；
> 但 1.4 的编译验证必须换环境。

---

### 🔜 阶段 2 — Host API dispatch：绿区实现

按 `02-Host-API映射表.md` 的绿区逐条实现，优先级：

1. `Tools.System.terminal.create/exec/screen/input` → Kelivo 已有 `PtySession`/`ProotCommand`，**纯适配**
2. `Tools.Files.*` → Kelivo `workspace` 文件 API
3. `Tools.System.sleep` → 直接实现
4. `Tools.Chat.*` / `Tools.Memory.*` / `Tools.Workflow.*` → 映射到 Kelivo 对应模块

**完成标志**：`super_admin.js` 能在 Kelivo 里执行 `ls -la` 并回传输出。

---

### 🔜 阶段 3 — 黄区补齐（需 Shizuku / Android API）

- `Tools.System.shell` / `setSetting` / 应用管理 / Intent / 通知
- 需要引入 **Shizuku** 依赖（Operit 用的是 `ShizukuAuthorizer.kt`，可参考其权限申请流程）

---

### 🔜 阶段 4 — 红区决策（需要你做取舍）

| 能力 | 选项 A | 选项 B |
|---|---|---|
| 设备自动化 `Tools.UI.*` | 移植 AccessibilityService（工作量大） | 只保留截图，去掉点击/滑动 |
| 浏览器 `Tools.Net.browser*` | 用 Kelivo webview 简化实现 | 直接裁剪，不加载 `browser.js` |
| `Tools.SoftwareSettings.*` | 重映射到 Kelivo 设置 | **建议直接删除** |

---

### ❌ 阶段 5 — 编译打包（本机无解）

**必须在 x86_64 + Android SDK + Flutter SDK 环境执行**，例如：
- 你的 PC（装了 Android Studio）
- 或 GitHub Actions（`ubuntu-latest` runner）

Gradle 配置建议（沿用 Operit 经验）：
```properties
org.gradle.jvmargs=-Xmx4g -XX:MaxMetaspaceSize=1g
org.gradle.vfs.watch=false
```

---

### ❌ 阶段 6 — 真机测试迭代

需要一台 Android 8.0+ / arm64-v8a 设备。
